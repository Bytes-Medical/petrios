## Architecture

Next.js 16 App Router application — a teaching management platform for NHS trainees. Multi-tenant with organizations and departments.

### Backend Pattern

All data mutations use **Next.js Server Actions** in `app/actions/`. There is no ORM — actions do auth checks and orchestration, then delegate table access to the data-access layer in `lib/db/` (see `lib/db/README.md`), the only code allowed to import Supabase for data-plane queries:
- `lib/db/client.ts` — `getDb()` (RLS-honoring) vs `getServiceDb()` (service-role, bypasses RLS; functions using it carry a JSDoc justification)
- `lib/supabase/server.ts` / `lib/supabase/client.ts` — underlying clients; direct use outside `lib/db/` is reserved for auth-plane calls (`supabase.auth.*`)

Public/visitor-facing actions (`submitFeedback`, `respondToInvitation`, `claimSlotByCode`, and `claimSlotAsMember`, which shares its claim path) return expected failures as `{ ok: false, message }` and throw only for unexpected errors, because Next masks thrown Server Action errors in production (spec/07). The Petrios Meet actions in `app/actions/meetings.ts` never throw: every failure, unexpected ones included, comes back as `{ ok: false, reason, message }` (logged without tokens, keys or emails).

### Auth & Middleware

- Supabase Auth. Sign-in methods: passwordless magic link (default; rate-limited via `lib/rate-limit.ts` + `login_link_requests`), Microsoft Entra ID SSO (`azure` provider, works with NHSmail), and email/password for admins. Session managed via cookies. See `spec/01-architecture.md` → "Sign-in methods".
- `proxy.ts` (Next 16 proxy convention, formerly middleware) — redirects unauthenticated users to `/login` using LOCAL JWT verification (`auth.getClaims()`, no network call; authorization stays in pages/actions/RLS — see spec/01). Public routes: `/`, `/login`, `/signup`, `/verify/*`, feedback pages, teacher RSVP pages.
- `lib/auth.ts` — helper functions: `getCurrentUser()`, `getCurrentOrgId()`, `requireAuth()`, `requireOrg()`, `isOrgAdmin()`, `isSuperAdmin()`, `isDepartmentModerator()`.
- Latency conventions (spec/07): pages fetch parallel-by-default (staged `Promise.all`), role checks are cached+concurrent, hot routes ship `loading.tsx` skeletons, mutations use `hooks/useActionWithRefresh` (pending spans action + refresh), heavy client libs load via dynamic wrappers (`SessionCalendarLazy`).

### Deployment (dual runtime)

Production runs on Cloudflare Workers (`@opennextjs/cloudflare` + `wrangler.jsonc`; spec/09, `docs/cloudflare-workers.md`): the Worker `petrios`, served only through the Workers Custom Domains `petrios.uk` and `app.petrios.uk` since 2026-10-11 (Render retired). The Docker/Node build (`output: 'standalone'`) remains for self-hosting; `.dockerignore` keeps every Cloudflare file out of the image. Every change must work on both runtimes (spec/07):
- `cfw/worker.ts` is the custom entry: its first import `cfw/yoga-install.ts` answers react-pdf's runtime yoga `WebAssembly.instantiate` with the module precompiled at upload (`cfw/yoga-redirect.ts`, regenerated each build); `public/fonts/*.ttf` ship as Data modules so `node:fs` font reads work at `/bundle/public/fonts`; `scheduled()` maps Cron Triggers to `/api/cron/*` (`cfw/cron.ts`) and dispatches only when `CRON_ENABLED` is exactly `"true"`.
- The top-level (staging) Worker has no cron triggers, no routes, `CRON_ENABLED="false"`, `OUTBOUND_EMAIL_ENABLED="false"` and `ROTA_INTEGRATION_ENABLED="false"` (it serves the production database, so `lib/email.ts` refuses every send except to `OUTBOUND_EMAIL_ALLOWLIST` addresses); only `env.production` has triggers. Production (`petrios`) is `env.production`, the only other wrangler environment (a reintroduced `env.production_preflight` is refused): `routes` is exactly the custom domains `petrios.uk` + `app.petrios.uk` (`PRODUCTION_CUSTOM_DOMAINS`; wrangler publishes them as the complete set, so a dropped hostname is detached and its Cloudflare-managed DNS record deleted; `www` is a zone-level 301, not the Worker), no plain routes, workers.dev off, the six crons, email on, `APP_URL=https://petrios.uk`. Deploy only via `npm run cf:deploy:production -- deploy [--dry-run]|rollback [<version-id>]` (`productionConfigProblems` in `scripts/cloudflare/lib.mjs`; deploy previews the custom-domain changeset and refuses removals, DNS conflicts, other Workers' hostnames and plain routes, runs wrangler with `CI=false` (a run without a terminal relies on that preview), and confirms domains/routes/crons from the API; rollback sends `wrangler rollback`'s deployment request itself, never forced (Cloudflare refuses it across a secret change, code 10220), code+vars only, never touching domains/routes/crons, refused onto a version with non-production vars; after a rollback never use `wrangler versions secret put`/`versions deploy`, which copy the rolled-back code: deploy a fixed main first; `preflight`/`live` are retired and refuse). The production Worker is the only scheduler of the crons against the database. `cf:deploy:staging` refuses a top-level name equal to the production Worker's (it would replace the live version and clear its crons) and a `--secrets-file` that names a `vars` key (wrangler would let it silently replace the var), a never-set name or an `APP_URL` fallback.
- `cf:build` overwrites OpenNext's compiled `.env` snapshot (`next-env.mjs`), patches OpenNext 4.1.9's bundled `cloudflare-node` response writer so streamed responses keep backpressure (fails if the code no longer matches; revisit on every OpenNext upgrade), and its guard fails if any local `.env*` secret value appears in the dry-run upload or static assets, or if the backpressure marker is missing. On Workers set `APP_URL`/`SUPABASE_URL`/`SUPABASE_ANON_KEY`/`JITSI_DOMAIN` (runtime-read; Petrios Meet `JAAS_*`/`JITSI_APP_*` are Worker secrets too) and never the `*_INTERNAL_URL` variables.
- Server clocks are UTC (Workers ignore `TZ`): server code formats dates via `lib/datetime.ts` (`formatInAppTimeZone`/`formatAppDate`/`formatAppDateTime`/`appDayKey`/`appWallClockToIso`) in `APP_TIME_ZONE`, never `toLocale*String` without a `timeZone`; client components rendered during SSR show timestamps through `components/LocalSessionDateTime.tsx`, except panels that must match server text (slot descriptions, Ops action times), which take the server's `appTimeZone()` as a `timeZone` prop because `APP_TIME_ZONE` is server-only.
- No floating promises on server paths: request paths wrap follow-up work in `after()` from `next/server` (waitUntil on Workers); crons await. Don't buffer whole documents/audio/PDFs where a stream works (128 MB isolate).

### Role Hierarchy

`super_admin` > `org_admin` > `department_admin` > `faculty` > `trainee`

Super admins are stored in a separate `super_admins` table. Other roles are in `organization_members.role`.

A user may be `department_admin` for multiple departments in one organization,
but never across organizations. Migration 044 enforces this in Postgres: a grant
in a new organization demotes prior cross-organization moderator roles to
`faculty` while preserving ordinary membership.

### Evidence-Based Attendance

The attendance system is an append-only evidence aggregation pipeline (documented in `spec/03-attendance.md`):
- New sessions use policy v2 and source priority `MODERATOR_CONFIRMATION` > `TEACHER` > `TEAMS` > `GROUP_CODE` > `SELF_CHECKIN` > `RECALL`; feedback is excluded. `RECALL` is created only by the guarded Audio Recap mastery RPC and means transparent catch-up recognition, never physical presence
- Among moderator decisions the **latest** `MODERATOR_CONFIRMATION` wins (observed_at, then created_at, then id), and a valid `RECALL` observed after an `ABSENT`/`EXCUSED` override wins over it (status-keyed, never reason-keyed). the SQL RPC applies it from migration 064, and `compute.ts` follows the same 064 marker (earliest-first until it exists, so both always agree; spec/03 parity cases P1–P9)
- `attendance_evidence` is append-only; policy-v2 insertion and recomputation are one transactional RPC
- Moderators finalize a complete roster into a numbered revision; reopening requires a reason and revokes canonical certificates
- Group codes are cryptographically random, stored as salted scrypt verifiers, rate-limited, and returned in clear only at generation
- Pure computation lives in `lib/attendance/compute.ts`; the database RPC mirrors it. The post-session cron consumes finalized results and never infers attendance

### Key Subsystems

- **Certificates**: Branded A4-landscape PDF generation via `@react-pdf/renderer` in `lib/certificates/pdf.tsx`. Departments configure up to four ordered teaching coordinators; names are snapshotted onto issued rows so later settings edits do not rewrite history. After an ended session's attendance governance is finalized, an accepted assignment is sufficient for a teaching certificate; attendee certificates still require current finalized `PRESENT`/`LATE` attendance. Registered recipients use `user_id`; accepted external teachers use invitation id + normalized email and receive the PDF by email attachment without an account. Teachers are excluded from duplicate attendee certificates. The moderator batch only inserts rows for registered recipients (their PDF renders on download); external teachers are its only batch-time render. Server action in `app/actions/certificates.ts`. Public verification at `/verify/[certificateId]`.
- **Email**: Resend REST API (`lib/email.ts`, a `getEmailClient()` adapter over `fetch`). Templates in `lib/email-templates.ts`. Used for teacher invitations, session reminders, and certificates.
- **Feedback**: Public/accountless but identified session feedback with QR code distribution. Name/email are stored, the server enforces the session window (one shared rule in `lib/feedback-window.ts`, also used by the public pages to show an open/closed notice), and one response per normalized email/session is allowed. Feedback never creates attendance or certificates. From the first response, moderators can generate an identity-field-omitted, name-stripped, welfare-screened AI teaching draft, edit/review it, and release the exact snapshotted narrative with question-level analytics. Reports based on fewer than five responses carry a prominent limited-evidence warning; only a zero-response report suppresses analytics. Teacher reports use a claimed delivery ledger; ordinary retries skip successful rows, while an explicit moderator resend may reacquire them and records a new audited attempt. The legacy “You said, we did” surface is inactive.
- **Session documents**: PDF/DOCX/PPTX up to 25 MiB in a private storage bucket, managed through `session_documents`. Moderators and accepted teachers upload; authorized session users view/download; moderators delete any document and uploaders delete their own (live object first, then metadata). Uploads go browser→Storage through a one-shot signed upload URL (`prepareSessionDocumentUpload` → PUT → `finalizeSessionDocumentUpload`, or `cancelSessionDocumentUpload` on a failed PUT); finalize stream-validates the stored object with bounded memory (size, SHA-256, magic bytes, marker scan, ZIP central directory) in `lib/session-documents-inspection.ts`. Downloads stream; no large Server Action body limit exists. Office files are basic-validated and downloaded rather than converted. This is not an antivirus/webviewer claim.
- **AI and speech**: `lib/ai/llm.ts` is the inference boundary; `lib/ai/provider.ts` resolves the provider and builds the Anthropic client (no calls); `lib/ai/anthropic-files.ts` handles Files API upload/delete/sweep (no inference). Provider: `LLM_PROVIDER` pin, else `ANTHROPIC_API_KEY` → **Anthropic Claude (default)** via the official `@anthropic-ai/sdk` (default model `claude-opus-5-5`, override `ANTHROPIC_MODEL`), else `OPENAI_API_KEY` → the optional OpenAI-compatible adapter (Chat Completions + Responses file inputs over `fetch`, `OPENAI_MODEL` default `gpt-5.5`, `OPENAI_BASE_URL`); both keys plus `OPENAI_BASE_URL` without a pin is a configuration error (AI off) so in-network traffic never silently moves. Anthropic calls always stream on the beta Messages endpoint with server-side refusal fallbacks (`fallbacks: 'default'`, `ANTHROPIC_FALLBACKS=off` to disable), never send `thinking`/sampling/prefill/forced `tool_choice`, and set `output_config.effort` explicitly per purpose. On an explicit moderator click, Audio Recap sends all currently available private session PDF/DOCX/PPTX sources (Anthropic: uploaded one at a time to the Files API — PDFs as bytes, DOCX/PPTX as bounded extracted text (`lib/ai/office-text.ts`) — with an opaque `petrios-ai-` name, 1-hour expiry, deletion in `finally`, and a daily orphan sweep in `ops-synthesis`), requires domain-limited hosted web research (`web_search_20260209`, direct, allow-listed; not forceable, so a post-check requires a completed search and an allow-listed source), and drafts a detailed ~5-minute recap (on Anthropic, the text after the last search result) whose primary evidence remains the documents. It stores source hashes plus clickable public research URL/title citations; document-set changes make the artifact unavailable, while later public-page changes do not automatically stale it. `lib/ai/tts.ts` is the one sanctioned text-to-speech boundary. Unless `TTS_PROVIDER` pins a provider, declaring either `ELEVENLABS_API_KEY` or `ELEVENLABS_VOICE_ID` selects ElevenLabs (both are required; one alone is an incomplete-configuration error with no OpenAI fallback), otherwise `OPENAI_API_KEY` selects OpenAI speech. With none of these, speech is unconfigured — an Anthropic + ElevenLabs deployment needs no OpenAI key. Only the draft recap script reaches the speech provider, and generated rows snapshot provider/model/voice. Moderators can recall approved audio to a private draft, preserving the existing preview while they re-synthesize, edit, or regenerate it; publication then requires approval again. Playback streams the `audio` column from PostgREST hex JSON (`lib/audio-hex-stream.ts`), pinned to the authorized `audio_revision`. Document inputs (Audio Recap, newsletter) are streamed from storage one at a time and verified against stored size/SHA-256 while streaming (`lib/ai/streaming-body.ts`): on Anthropic into one Files API upload per document, on the OpenAI-compatible adapter into a chunked Responses request — so a custom `OPENAI_BASE_URL` must accept chunked `/responses` file-input bodies without redirects and support `web_search` for document recaps, and a custom `ANTHROPIC_BASE_URL` must pass `anthropic-beta`, the Files API (chunked multipart `POST /v1/files` without redirects) and web search.
- **Petrios Meet (Jitsi video)** (spec/04, operator guide `docs/petrios-meet.md`): `JITSI` sessions get a room `Petrios-<session uuid>` DERIVED from the id. `lib/meeting/config.ts` (`getMeetingConfig`, server-only, logs a config error once) resolves ONE mode: **jaas** (all three `JAAS_*` → 8x8.vc, embedded, RS256 passes), **self-hosted** (`JITSI_DOMAIN`; HS256 passes with `JITSI_APP_ID`+`JITSI_APP_SECRET`, else open rooms; moderator/guest guarantees need server settings, docs/self-hosting.md), **public** (default meet.jit.si, never embedded — 5-minute embed cut-off — new tab, first arrival signs in). Partial config = unavailable, never a silent fallback. `app/actions/meetings.ts` mints a fresh room pass per join (PUBLISHED, room window start − 30 … end + 30 min on the server clock, one room, `exp ≤ min(now + 4 h, close)`, moderator = department moderator or ACCEPTED teacher, claims = name + per-session pseudonym + moderator flag, never an email). External teachers get one from their ACCEPTED RSVP code ONLY when `TEACHER_INVITATIONS_RLS_LOCKED=true` (set after migration 062, which drops 017's public `teacher_invitations` policies, is applied and verified: `docs/security/rls-lockdown.md`); the same flag gates the RSVP page's service-role session read. The panel (`JitsiMeetingPanel` + `MeetingEmbed`; pure logic in `lib/meeting/panel-state.ts` and `embed-events.ts`) attempts member self check-in on join (hosts skipped; "already checked in" when code/self evidence exists; one automatic retry when the check-in window opens). `sessionMeetingUrl(session, audience)` in `lib/jitsi.ts` is the single outbound resolver and never throws: members always get `APP_URL/sessions/<id>` (proxy keeps it as `next` through sign-in); external teachers get the raw room in public/open modes, else their RSVP URL; Teams/hybrid the stored link. CSP/Permissions-Policy delegate only the embedded origin.
- **Cron jobs**: `app/api/cron/post-session-reports` (canonical attendee certificates + claimed/retryable delivery after attendance finalization; every run also awaits the deletion-only rota purge, `rota_purged` in the response), `app/api/cron/session-reminders` (reminder emails ~24h before a session), `app/api/cron/recall-send` (published catch-up invites to finalized absent or excused expected attendees), and `app/api/cron/recall-awards` (retry catch-up certificate/PDF email). They authenticate with `Authorization: Bearer CRON_SECRET`; exact idempotency/failure behavior is subsystem-specific. Long jobs take a per-run work budget (`lib/run-budget.ts`, ~8,000 estimated subrequests / 10 min; `post-session-reports` gives each session a capped slice so one session cannot starve the batch, and confirms a capped bulk-ledger miss with an exact lookup) and leave unreached recipients in a per-recipient `session_deliveries` ledger with the watermark open (reminders use `delivery_type = 'SESSION_REMINDER'`, related_id = session id); `recall-awards` takes 10 completions per run, two at a time (`lib/concurrency.ts`).
- **Evidence Engine (spec/08)**: trainee attendance evidence + reflections + ARCP portfolio packs (`app/actions/portfolio.ts`, `lib/portfolio/*`, `session_reflections` + `portfolio_packs` tables, public verify at `/verify/pack/[code]`) and teacher appraisal dossiers (Teaching tab). Curriculum mapping is retired from the active product; its historical tables remain migration-safe and unread by active flows.
- **Platform layer (spec/09)**: public API `/api/v1` (org-scoped `pt_` bearer tokens, hashed at rest, scoped; thin routes over `lib/db/api-reads.ts`; OpenAPI at `public/openapi.json`), signed webhooks (`lib/webhooks.ts` — one attempt, never rejects; request paths register it with `after()`, crons await it; HMAC `X-Petrios-Signature`, SSRF-guarded; events: session.published, attendance.computed, certificate.issued, slot.claimed), federation (`lib/federation.ts` Ed25519 signed teaching records, `/.well-known/petrios`, `/verify/record`), self-hosting (SMTP transport, LLM provider choice incl. `OPENAI_BASE_URL` for in-network OpenAI-compatible models, Docker + `/api/health` + `scripts/migrate.mjs`; `docs/self-hosting.md`). Federated benchmarking is specified (spec/10, petrios-benchmark/v1) but not implemented.
- **Public site (spec/07, spec/13)**: `components/hud/` Clinical HUD tokens and components scoped by `HudShell` (`data-hud-root`, one CSS module `hud.module.css`, `:where()` element rules); every public marketing/legal page renders inside it, and the signed-in app never imports it (`Button`, `Wordmark`, `Nav`, `globals.css` stay untouched). Day is the default; Night / Match device are stored in the first-party `petrios-display` cookie, read on the server (`lib/public-display.ts`) and disclosed on /privacy. The landing h1 is the CSS-only calibration strip (`CalibrationStrip` + chunked clip-path `Typewriter`, no canvas or script). Readouts and spec strips carry a never-rendered `source` and quote verified facts only.
- **Compliance boundary (spec/13)**: public `/privacy`, `/privacy/choices`, `/subprocessors`, and `/data-processing-agreement`; runtime disclosure config in `lib/compliance.ts`; security headers applied by `proxy.ts` via `lib/security-headers.ts` (static assets excluded); contrast-safe small-text tokens. Missing controller/region/transfer facts stay visibly missing and repository evidence/scanner scores are never presented as certification.
- **Petrios Recall (spec/08)**: Recap generation also drafts exactly five spoken-script-bound questions (gateway purpose `recall_questions`). A moderator edits and publishes an immutable revision only after the matching ~5-minute document-led/researched Audio Recap and attendance are approved/finalized. A token deep link requires the exact signed-in registered expected attendee whose finalized result is ABSENT or EXCUSED (EXCUSED once migration 064 is applied: the app reads `recall_catchup_eligible_statuses_v1()` and falls back to `['ABSENT']` before it); server-backed playback unlocks up to three attempts and only 5/5 calls the dedicated transaction that appends `RECALL`, changes same-revision ABSENT/EXCUSED to transparent catch-up PRESENT, and queues an `AUDIO_RECAP_CATCH_UP` certificate/PDF email. Generic evidence paths cannot write RECALL. The Recall tab retains aggregate-only analytics (cohorts under five suppressed; no individual tool exposure).
- **Rota availability (spec/14)**: off by default; on only when `ROTA_INTEGRATION_ENABLED` is exactly `"true"`, `ROTA_IDENTITY_SECRET` is ≥ 32 bytes, migrations 063 **and** 064 are applied (rota is "not installed" until 064's `recall_catchup_eligible_statuses_v1()` includes `EXCUSED`, so an excusal never removes a catch-up route), the org is enabled in Settings (requires a DPIA reference + privacy-notice confirmation; DB check) and the department is enrolled. The rota coordinator (narrow `rota_uploaders` grant) or a moderator uploads a CSV weekly at `/departments/[id]/rota`; parsing, column mapping, the code dictionary (letters A/D/N/X/L only, **no leave category anywhere**; sickness is never distinguishable) and 46 h post-night rest run **in the browser** (`lib/rota/*`, no `xlsx` dep), which sends only a minimised day-template payload split into WORKED (past) and PLANNED (today on) batches. Identifiers are matched via keyed HMAC links (`rota_identity_links`; staff id → email → profile email; names never leave the browser, every link is moderator-confirmed with its origin decided server-side, and moderators can also link by staff number via `link_rota_identity_v1`). Membership-oracle bound: one atomic `record_rota_match_preview_v1` per upload id (≤ 10/day per uploader), the ingest requires that preview by the same caller and ≤ 1 batch per kind per upload, uploader rows carry HMAC row proofs from the preview, and an uploader's result carries counts only (no flag/decision/link counts); the batch audit stores a keyed digest, never a plain hash. Unknown days are never sent as cleared; only PUBLISHED sessions get flags; the size cap is per session. Then `ingest_rota_batch_v1` stores per-session flags **only for unavailable trainees** (deny-all `rota_*` tables, DAL `lib/db/rota.ts`, read via the `rota_visible_session_flags` view). After a session ends, the manage Attendance tab's Expected roster panel suggests "excused (rostered unavailable)"; each row is confirmed individually through the transactional `confirm_rota_excusal_v1` (MC `EXCUSED`, `reason_code: ROTA_UNAVAILABLE`, `rota_batch_id`; refuses a trainee with RECALL catch-up evidence, `rota:caught_up`, and the panel hides them), never in bulk, and finalize never reads rota data (its confirmation only warns in the browser about undecided suggestions). Dismiss/contest are RPCs that also write `ROTA_SUGGESTION_DISMISSED`/`ROTA_FLAG_CONTESTED` activity events. Guards in `lib/rota/access.ts` (`requireRotaModerator` refuses super admins acting in another org; deletion-only cleanup guards let org admins disable/un-enrol/remove uploaders and moderators revoke links with the switch off). A trainee of the department cannot hold the uploader grant. Trainees see and can contest their own flag (state-specific notice, exception reports go to the educational supervisor). A session time change/cancel or member removal deletes flags; the deletion-only purge (30-day default after finalization/Recall close, 90-day hard cap, batch audit 12 months) runs on every ingest and every `post-session-reports` run even with the switch off. Missing 063 objects map to `RotaNotInstalledError` = "unavailable", never a 500. Scheduling counts and the push API are not built. Operator guide `docs/rota.md`.
- **Address book**: org-scoped `external_contacts` + `contact_groups` (deny-all RLS, service-role DAL `lib/db/external-contacts.ts`, managed in Settings). Contacts auto-captured from external teacher invitations/RSVPs; groups are the audience unit for slot publications.
- **Teaching slots (Calendly-style)**: moderators bulk-create open slots (`/departments/[id]/schedule`), publish them to contact groups and/or registered members, and invitees claim first-come-first-served (atomic CAS in `lib/db/teaching-slots.ts`). Claiming creates a DRAFT session with the claimer attached as teacher; externals claim via the public `/claim/[code]` page, members via the dashboard Teaching tab. Open slots render as "Available" events on `SessionCalendar` (`slots` prop). Bulk creation can split each day into 10–20-min lightning micro-slots (`splitSlotDraft`/`isLightningSlot` in `lib/slot-schedule.ts`). Chosen slot days/times are wall-clock times in `APP_TIME_ZONE`, converted to UTC on the server (`appWallClockToIso`).
- **Petrios Ops (AI agent layer)**: additive agent layer under `lib/ops/` + `/ops` routes + `ops_*` tables (migration 036 onward, all deny-all RLS, accessed only via `lib/db/ops.ts`; read-only core-table queries live in `lib/db/ops-reads.ts`). Hard invariants: (1) NO outbound email without an approved `ops_pending_actions` row — `lib/ops/executors.ts` is the only Ops send path; (2) all LLM calls go through `lib/ops/gateway.ts` (`opsInference`, purpose allow-list, audit steps store prompt HASHES + token counts, never text) — the one exception is the assistant tool loop in `lib/ops/agent-loop.ts`; never call an LLM provider API anywhere else besides `lib/ai/llm.ts` (`lib/ai/provider.ts` only builds the client; `lib/ai/anthropic-files.ts` only uploads/deletes files); (3) `OPS_ENABLED=false` kills every Ops surface; (4) feedback synthesis (`lib/ops/synthesis.ts`) strips names and routes welfare-signal content to humans (`requires_human_review`), and the layer never evaluates trainee performance. Crons: `ops-weekly` (speaker chases → approval queue and low-score alerts), `ops-synthesis` (feedback syntheses + thank-you drafts; with Anthropic, every run also sweeps orphaned Files API uploads). Newsletters are moderator-triggered, department-scoped, document-led, editable one-page drafts rendered by the pure `lib/ops/newsletter-render.ts` ("Monitor strip" HTML + text/plain; full/compact/index tiers stepping down toward a 60 KiB budget, index final and hard-capped at 96 KiB so Gmail never clips the unsubscribe footer) from a render snapshot taken once at generation (`content.render`: names, timing, teachers, source-current Audio Recaps, coordinators, the next seven local days); explicit approval sends the reviewed revision through a per-recipient delivery ledger, and sending never re-reads the snapshot. Organiser-only chat assistant at `/ops/assistant` (tools in `lib/ops/tools.ts`, org scope always from the authenticated caller) — **disabled by default**: every chat action refuses and the page 404s unless `OPS_ASSISTANT_ENABLED=true` (deployment safety decision). Approvals surface: `ApprovalsBell` in the nav + `/ops` queue. Public unsubscribe at `/ops/unsubscribe/[token]` (HMAC token, `lib/ops/newsletter.ts`).

### Database

PostgreSQL via Supabase with Row-Level Security on all tables. Migration 062 (`docs/security/rls-lockdown.md`) removed the anon/cross-tenant holes: write new policies with the row-scoped helpers `is_org_member_of`/`is_org_admin_of`/`is_department_moderator_in`/`is_session_moderator_in` (never `is_org_admin()` alone), never add SELECT visibility to `organization_members`/`department_members` (a `FOR ALL` policy does; `getCurrentOrgId()` picks the newest visible own row), and revoke `SECURITY DEFINER` RPCs `FROM PUBLIC, anon, authenticated` (spec/02). Migrations in `supabase/migrations/` (numbered files, applied in order). Core tables include `organizations`, memberships/departments, `sessions`, teacher assignments/invitations, attendance evidence/results/rosters/activity, identified feedback/report deliveries, certificates, and private session-document metadata.

All shared TypeScript interfaces are in `lib/types.ts`. User roles defined in `lib/auth.ts` as `UserRole` type.
